02 / ARITHMETIC LAB

Choose what overflow means.

Change a type, operands and policy. Decimal strings stay exact through 128 bits; JavaScript floating-point numbers are never used for integer arithmetic here.

Explicit unchecked conversion

Low bits are retained. This can be intentional, but a changed value is not an exact result.

Checked expression + conversion

Overflow raises an exception. A surrounding application chooses how to recover.

Selected package policy



Failures, defaults and programmer errors
Expected arithmetic failures use statuses. A failed Try operation writes zero; that zero is a cleared output, not evidence of success. Default NumericResult<T> is Uninitialized. Its Value accessor throws on misuse; inspect the status or use TryGetValue. Undefined arithmetic policy bytes throw ArgumentOutOfRangeException before arithmetic, even if the operands would succeed. Policies apply to Add/Subtract/Multiply; policy-driven Divide/Negate are not provided.

04 / DOMAIN LAB
An Int32 is not a queue depth.


The primitive easily represents 64. This queue contract does not. Its generated Try path always rejects invalid results; its configured Saturate helper clamps to the domain’s 0–63 endpoints.


Ordinary checked Int32
Generated TryAdd
Generated Add / Saturate
Current depth, big-endian 2 bytes
[BoundedInteger(typeof(int), "0", "63",
    OverflowPolicy = ArithmeticPolicy.Saturate,
    DefaultPolicy = DefaultValuePolicy.ZeroValid,
    SerializationWidth = 2,
    Endianness = IntegerEndianness.BigEndian,
    Unit = "entries")]
public readonly partial struct QueueDepth;

// In a method:
QueueDepth.TryCreate(62, out var depth);
var error = depth.TryAdd(2, out var next);
// OutOfRange; next is default (valid zero under ZeroValid).
var capped = depth.Add(2);
// Success: capped.Value represents 63 entries.

Span<byte> bytes = stackalloc byte[2];
depth.TryWrite(bytes, out int written);
// 00 3E: the original value, 62.


What these annotations actually implement
DefaultPolicy chooses invalid-by-default or ZeroValid (which requires zero in the domain). TextPolicy selects invariant decimal or hexadecimal span text. SerializationWidth and Endianness select a validated fixed-width codec. Unit is metadata—not dimensional analysis or unit conversion. Explicit conversions remain exact. Generator diagnostics reject unsupported declarations, options and member collisions.
Generated Wrap first wraps within the primitive type, then checks the domain; it does not wrap 64 back to zero within a 0–63 queue. Write/format destination storage and count-output storage must be distinct.

06 / BATCH CONTRACT
Call AddBatch. It picks the SIMD width.


A lane is one pair of elements at the same position in two input arrays. Adding two arrays of 1,000 integers gives you 1,000 lanes. SIMD256 can add eight pairs at once, and AVX-512 can add sixteen. Call SafeInteger.AddBatch and it selects the available path and handles any leftover pairs.




Green: exact vector resultRose: overflow/underflow → zeroSand: scalar tail or fallback


var outcome = SafeInteger.AddBatch(left, right, values, errors);
if (!outcome.IsSuccess) { /* handle buffer-contract failure */ }
// VectorWidthUsed is optional diagnostic information.
// Inspect errors[i] before consuming values[i].


Conceptual visualization only: it does not detect this browser’s ISA or execute SIMD. On supported hardware, batches of at least 256 lanes start with AVX-512. Remaining lanes use SIMD256, SIMD128 and scalar as available. The preview shows the first 24 lanes. Buffer errors occur before writes; read-only inputs may alias, written prefixes must be disjoint, and destination suffixes are preserved. SIMD currently covers Int32 batch addition.


In a repeated sweep at 262,147 lanes, AVX-512 took 37–42% longer than SIMD256 on the tested Xeon 8573C hosts and about 24% less time on the tested AMD EPYC 9V74. The Xeon 6975P-C had a smaller SIMD256 lead of about 2–3%. Dispatch has no large-batch cutoff. Timing samples and CPU details




07 / PUT IT TO WORK
Start at the boundary that needs a contract.


Good places to start
  • Packet fields and telemetry that must reject unrepresentable values.
  • Queue depths, counters and bounded engineering parameters.
  • Simulation kernels where an expected overflow should return data.
  • Independent Int32 buffers needing a consistent batch failure contract.
Keep a simple checked expression where exceptions already match the application’s failure model. Use standard generic math directly when its checked/saturating/truncating behavior is the whole requirement.
Wire up the layers
dotnet add package SharpSafeNumerics.Core --version 0.1.0-rc.1
dotnet add package SharpSafeNumerics.Generator --version 0.1.0-rc.1
dotnet add package SharpSafeNumerics.Analyzers --version 0.1.0-rc.1
Package coordinates shown for the candidate. This guide does not imply that RC1 is published. Until publication, build the repository packages and restore from that local feed. Compiler extensions belong in development/analyzer references; they are not arithmetic runtime dependencies.


using SharpSafeNumerics;

// Expected bad input is ordinary data, not an exception.
var error = SafeInteger.TryConvert<int, byte>(sensorValue, out byte field);
if (error != ArithmeticError.None)
    return; // Reject/log/recover according to your application.

// Intentional saturation is named at the call site.
var capped = SafeInteger.Add((byte)250, (byte)10, ArithmeticPolicy.Saturate);
if (capped.TryGetValue(out byte value))
    Consume(value); // 255

// Within your class/method, apply the analyzer's strict scope.
[StrictNumeric]
static ArithmeticError Add(int a, int b, out int value)
    => SafeInteger.TryAdd(a, b, out value);


Examples show method-body fragments or declarations as labeled. The generator supports its documented top-level partial struct shapes. Core uses BCL-only generic math and no runtime reflection. 09 / IEEE DECIMAL
Choose rounding and inspect the flags.


The optional Decimal package provides explicit rounding and exception flags for Decimal32, Decimal64 and Decimal128. Use SafeDecimal when you want finite, exact-by-default arithmetic. Use IeeeDecimal<T> when your calculation needs IEEE values such as infinity, signed zero or NaN payloads.




0.3333333333333333 · Inexact


This offline lab displays the expected results for this example. Run the equivalent C# with .NET 11 and the SharpSafeNumerics.Decimal package.


using System.Numerics;
using SharpSafeNumerics;

var context = new IeeeDecimalContext(IeeeDecimalRounding.TowardPositive);
var third = IeeeDecimal<Decimal64>.Divide(Decimal64.One, Decimal64.CreateChecked(3), context);
Console.WriteLine($"{third.Value} ({third.Flags})");
