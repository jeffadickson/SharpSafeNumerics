# Week qualification runner design

The runner is an orchestration-only PowerShell wrapper over the established workstation runner's tool selection, portable bootstrap, contained process jobs, logging, and scoped Git commit checks. Its script and imported helper source are pinned by hash at startup. PowerShell5.1 can launch it; the existing portable bootstrap selects/installs modern PowerShell only if needed. Managed .NET11 SDK candidates are reused before any isolated SDK installation; no Dafny, native compiler, or unrelated tool runtime installation occurs.

The default duration is168 hours, report interval24 hours, and chunk duration3600 seconds. Each child receives a fresh summary path, positive advancing seed, and exact40-hex source revision. Counterexamples/invalid CLI are fatal; exit3 is retained as inconclusive and permits later chunks, making final statusIncomplete. A five-minute maximum cleanup/report reserve fits within the original absolute deadline. No process memory caps apply.

The unique stable qualification/issue-1/week-* branch contains bounded results only. A separate new detached worktree and isolated build outputs are created each day after fetching the configured source branch. The revision is immutable during each chunk. Successful build, decimal regression and short harness preflight are required before activation. Failed updates are immediately reported, explicitly retain the last successful revision, and make final statusIncomplete; initial setup failure is fatal. PinnedSource or a literal40-hex SourceRef disables following. Numerical counters are summarized by source revision, never merged across revisions.

Checkpoints are atomically replaced with a previous-copy recovery file. The original deadline, source/report provenance, next seed index, pending upload manifests and partial chunk records survive restart. Resume marks an active uncertain chunkInterrupted and never overwrites/reuses its summary. Unknown local changes or a foreign checkout/branch prevent resumption. A task-owned exclusive run lock prevents two orchestrators from running the same checkpoint.

Every daily/final report is committed through the existing scoped-path/parent/identity validator. Push success is independently verified by remote branch SHA and exact Git blob hashes. Only explicitly owned local report staging files and small child summary JSON files actually included byte-for-byte in that verified commit may be deleted by default. KeepResults disables cleanup. Failed/unverified uploads remain pending for retry. Raw stdout/stderr and JSONL checkpoints not uploaded remain local. Cleanup validates an ownership marker, absolute child paths, all parent components and non-reparse files; it never deletes directories, checkouts, source or foreign files.

Tests use side-effect-free plans and imported pure scheduling/checkpoint/cleanup functions with fake clocks/process/report callbacks. They cover daily boundaries, new-source activation/fallback, inconclusive and fatal outcomes, immutable seed/source metadata, interrupted resume, failed publication, path/reparse defenses, and retention. No week-long run starts during development.
